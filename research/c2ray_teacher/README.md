# Native C²-Ray H+He teacher

This adapter runs the original C²-Ray transport, chemistry and temperature
solver on prescribed source fields generated by this 21cmFAST branch. It is a
separate RT teacher workflow; it does not replace 21cmFAST's production
ionization routine or train a network.

The numerical implementation is pinned to
[`garrelt/C2-Ray3Dm1D_Helium` at `a363656ff1c3b4b4c7334f398578d8c469154515`](https://github.com/garrelt/C2-Ray3Dm1D_Helium/tree/a363656ff1c3b4b4c7334f398578d8c469154515).
`upstream_lock.json` verifies the upstream files. `build.py` copies the numerical
sources byte-for-byte and compiles them with the external `driver.F90`.
Only grid size, cosmological parameters and helium abundance configuration
modules are generated. The upstream repository is GPL-3.0 licensed; retain its
license and attribution when distributing a combined build.

## Physical input

The current source adapter uses `research/pc_evolution/native_history.py`:

- Qin20 starting astrophysical parameters with deterministic L-INTEGRAL ACG
  sources. Native Park photon correction, MCGs, X-ray/spin-temperature evolution,
  native recombinations and UV feedback are disabled for source generation.
  C²-Ray itself evolves recombination, collisional ionization and temperature.
- Source histories use the same initial conditions at every redshift. Escaped
  emissivity is obtained from the instantaneous source prescription, not by
  differencing cumulative ionization fields.
- Gas density contrast is frozen at `reference_z`; proper density dilutes as
  `(1 + z)^3`. Source evolution is prescribed and does not respond to the new RT
  solution. This is not radiation hydrodynamics or an exact full-Qin20 run.
- The native photon normalization is `N_b0 = n_H + n_He`, the number of nuclei.
  `Q = native_rate * N_b0 * comoving_native_cell_volume` gives photons/s.
  Escape fraction and density deposition are not applied again. C²-Ray's
  density input is also total H+He nuclei per proper cubic centimetre.
- Time integration preserves the piecewise-linear endpoint emission budget.
  Density and proper volume use each transport step's cosmic-time midpoint;
  their product preserves the gas atom count. C²-Ray's original thermal cooling
  prescription, including its matter-dominated Hubble rate, is retained.
- Source positions remain at the original coarse cell centres. Refinement must
  be odd (for example 1 then 3), because the upstream integer-centre source
  representation cannot preserve these positions under even refinement.

The initial state is configurable, with defaults of 100 K, `xHII=xHeII=1e-6`
and `xHeIII=1e-12`. Starting at finite redshift does not supply earlier emission.
The upstream blackbody spectrum defaults to 50,000 K. These assumptions require
validation before using the output as training truth.

## Gadi

From an updated, committed checkout of `Photon_conserving`:

```bash
bash research/c2ray_teacher/gadi_prepare.sh --submit
```

Preparation archives this branch's exact HEAD and the pinned C²-Ray sources,
records hashes and compiler/runtime versions, then submits through `qsub`.
The compute job does not need network access. Default allocation is 32 CPUs,
128 GB, 24 hours on `normal`, project `qp00`. The RT layout is 4 MPI ranks ×
8 OpenMP threads. Source generation also uses the allocated CPUs.

The default first run is a pilot: 50 cMpc, `16³` RT/source cells, `48³` initial
density grid, seed 1234, redshift 20 to 5 with 30 transport intervals. It runs
1-, 8- and 32-CPU consistency cases before the prescribed cosmological history.
This pilot is not a high-resolution or spatially converged training set.

The existing runtime is reused from
`/g/data/qp00/sz4640/21cmfast_runs/large_pc_5e40d8ab21_20261024T042855_XhUc`.
Set `C2_RUNTIME_PARENT` if that run was moved; it must contain `runtime.env` and
a compatible `venv/bin/python`. `C2_PYTHON` can select a different interpreter.
The preparation and PBS scripts verify the selected compiled 21cmFAST runtime.

Geometry and allocation overrides include `C2_DIMENSION`,
`C2_HIGHRES_DIMENSION`, `C2_BOX_LEN`, `C2_SEED`, `C2_Z_START`, `C2_Z_END`,
`C2_INTERVALS`, `C2_REFERENCE_Z`, `C2_WORKERS`, `C2_QUEUE`, `C2_MEM`,
`C2_WALLTIME` and `C2_RUN_ROOT`. The workflow creates a fresh directory under
`/g/data/qp00/sz4640/21cmfast_runs/c2ray_teacher_*`; it never overwrites a previous
result. There is no resume support: prepare a fresh directory after failure.

## Direct execution and existing histories

Create a JSON configuration and run:

```bash
python research/c2ray_teacher/runner.py \
  --config config.json --output /absolute/new/results \
  --upstream /absolute/pinned/C2-Ray3Dm1D_Helium --workers 32
```

To reuse an existing compatible native fixture, set `"history"` to the absolute
path of `native_history.npz` in the configuration. Set `"refinement": 3` for
source-position-preserving gas subdivision and `"time_substeps": 2` for a
smaller RT step. Repeated piecewise-constant gas subdivision does not add new
cosmological density information. New native IC/source grids are a different
convergence test and must be treated separately.

GNU Fortran and OpenMPI are required. `MPIFC` chooses the compiler wrapper and
`C2_MPIRUN` the MPI launcher. The runner uses fresh working directories for each
native case because upstream logs append. Dimension must be at least 16.
Thermal evolution is required: the unchanged upstream isothermal initializer
accesses unallocated heating tables. The adapter rejects that configuration
instead of modifying the solver. Initial species fractions must be interior
to their physical bounds.

## Outputs and acceptance

Keep the entire results directory, including physical input/provenance,
native binary output, native logs, `states.npz`, `summary.json`, and parallel
benchmark diagnostics. The state payload includes hydrogen and helium ion
fractions, temperature, proper density, time-averaged fractions and species
photoionization rates. It is sufficient to inspect local evolution rather than
only a global neutral fraction.

`radiation_ionizations_time_average_estimate` estimates radiation-driven
**ionization events**, including secondary ionizations from photoelectrons.
The unchanged upstream adds these secondary contributions to the exported
`Gamma_HI_s` and `Gamma_HeI_s`; `Gamma_HeII_s` contains primary photoionizations.
An event count above the emitted photon count is therefore not evidence of
photon creation. In addition, the exported time-averaged fractions follow the
global chemistry update, whereas the effective rates come from the preceding
transport pass. Their product is an iteration-staggered estimate, not an exact
time integral or a measured primary-photon absorption count. It must not be
added to the escaped-photon diagnostic to assert photon closure.

Diagnostic schema 2 records these definitions in `summary.json` and the
`states.npz` metadata. Earlier outputs called the identical value
`photoabsorptions_time_average_estimate`; interpret that legacy field as the
secondary-inclusive event estimate above. Only the label and documentation
changed: existing simulation values remain usable without rerunning RT.

`COMPLETED` means the adapter, native convergence checks and bounded-state
checks passed. It does **not** certify spatial, temporal or angular convergence,
exact global photon closure, or suitability as final training truth.

Unchanged upstream limitations are explicitly recorded:

1. Its blackbody normalization and sub-band table quadratures differ. The
   measured `sum(bb_photo_thick_table(0,:))/S_star` is approximately
   **1.0153572222** with the pinned defaults. Both the nominal emitted budget
   and measured table normalization are retained; no hidden renormalization
   is applied.
2. Periodic density wrapping covers one source-centred domain. Photons leaving
   that tracing domain are not stored and reintroduced in subsequent intervals.
   This is not a closed, periodically recycled photon box.
3. Native photon-statistics counters are raw diagnostics, not an independent
   exact H/He/thermal conservation certificate. Temperature-dependent and
   species bookkeeping in that routine need separate interpretation. The
   current output does not separately count primary photon absorptions and
   photoelectron secondary ionizations.
4. Transport uses a quasistatic radiation field; it is not a finite-light-speed
   evolution. The chemistry and temperature implementation is preserved.
5. Source transport is parallel, but chemistry work and MPI overhead limit
   scaling. Small validation grids can run slower with more MPI ranks.

Before training, independently test front propagation, multiple-source overlap,
shadowing, thermal evolution, timestep refinement, spatial refinement, box-size
dependence and emitted/absorbed/escaped budgets. Validate both matched-state
morphology and evolution; a small global residual alone is insufficient.

## Local validation

```bash
uv run python -m pytest -q research/c2ray_teacher
uv run ruff check research/c2ray_teacher
```

`test_native.py` is an opt-in actual-kernel test. Set
`C2RAY_TEST_EXECUTABLE` to a compiled backend to check a thermal emission interval,
a following zero-emission interval and OpenMP consistency. The ordinary tests
cover unit conversion, source placement, time regrouping, bounds, build locking,
binary I/O and Gadi orchestration without requiring a Fortran compiler.

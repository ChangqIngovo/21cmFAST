# Paired emulator training on Gadi

The launcher runs `train_and_validate.py` using the collection generated by
`generate_teachers.py`. It fits the two predeclared feature configurations on
164 training snapshots, selects using 28 validation snapshots, freezes the
selected checkpoint, and then evaluates the 28 blind snapshots and the separate
resolution/volume transfer campaigns. The unchanged previous checkpoint is
scored on the same validation inputs and objective as both trained candidates.
It remains eligible for selection and wins exact ties; it also serves as the
fixed reference in the later benchmarks. Blind and transfer results never
enter selection.

After pulling the committed branch, provide the three absolute paths below.
`PC_PYTHON` must name an existing environment with the native 21cmFAST extension
and scientific dependencies. If it requires Gadi modules, set `PC_RUNTIME_ENV`
to its existing `runtime.env`; otherwise omit that assignment.

```bash
cd "/g/data/${PROJECT}/${USER}/21cmFAST"
git switch matched-photon-conservation
git pull --ff-only origin matched-photon-conservation

PC_PYTHON=/absolute/path/to/native-environment/bin/python \
PC_RUNTIME_ENV=/absolute/path/to/native-runtime/runtime.env \
PC_WORKERS=2 PC_THREADS=2 PC_NCPUS=4 \
PC_FRAME_CACHE_MIB=1024 \
PC_MEM=16GB PC_WALLTIME=24:00:00 \
bash research/pc_analytic_emulator/completion_20261116/reproduction/gadi_train_and_validate.sh \
  --campaign-root /absolute/path/to/generated-campaign \
  --previous-model /absolute/path/to/previous-emulator/model \
  --output "/g/data/${PROJECT}/${USER}/21cmfast_runs/emulator_completion_new" \
  --submit
```

The campaign root must contain `training_collection/collection_manifest.json`,
`teacher_blind`, `teacher_transfer_resolution`, and `teacher_transfer_volume`
from the generation workflow. Original referenced teacher archives must remain
at the paths recorded in the collection. Use `generate_teachers.py` on Gadi to
produce a new local collection; copying a collection JSON alone does not copy
its data or make its original absolute paths portable.

Omit `--submit` to prepare without scheduling. The new output directory contains
the committed source snapshot, runtime settings, SHA256 guards, PBS script, and
`resubmit.sh`. To resume the same run after an infrastructure interruption:

```bash
bash "/g/data/${PROJECT}/${USER}/21cmfast_runs/emulator_completion_new/resubmit.sh"
```

Completed trial checkpoints are verified and reused. Do not edit the frozen
`source`, settings, runtime file, or model artifacts in place; a changed protocol
requires a fresh output directory. Results are under `results/`, including
`selection.json`, the self-contained `model/`, and `benchmarks/` diagnostics.
PBS output is under `pbs_logs/`; `run_JOBID.log` records execution. The launcher
checks its committed source and interpreter binary before and after execution;
the workflow separately audits teacher receipts, model files, and selection.

Resource controls are `PC_PROJECT` (default `qp00`), `PC_QUEUE` (`normal`),
`PC_STORAGE` (`gdata/qp00+scratch/qp00`), `PC_WORKERS`, `PC_THREADS`, `PC_NCPUS`,
`PC_MEM`, `PC_WALLTIME`, and `PC_RAYS` (4096 per MFP phase). Worker/thread choices
are recorded in the frozen protocol and must fit one compute node. This
launcher does not install packages or choose environment modules.

`PC_FRAME_CACHE_MIB` caps cached arrays **per worker**. Its default remains
512 MiB; `0` disables storage. The expanded local-feature dataset needs about
564 MiB including frozen-base predictions, so the example explicitly requests
1024 MiB to retain it. Two workers permit at most 2 GiB of cached arrays under
that setting; model activations, optimizer state and library memory are
additional. The cap is recorded in the frozen protocol and does not change the
fitted objective, data order or model arithmetic.
